7. END-TO-END OPD GOLDEN PATH (RECOMMENDED TEST SCRIPT)
--------------------------------------------------------------------------------

This is the main Indian OPD flow currently implemented:

STEP 1 — Patient requests OPD
  Login: shubham@gmail.com / Kadam@123
  Go to: Request OPD (/patient/request-opd)
  Select: Health360 Hospital → Main Campus → optional doctor
  Enter visit reason → Submit
  Verify: My OPD today (/patient/opd) shows queue entry

STEP 2 — Reception sees request in queue
  Login: reception.test@health360.test (create first — Section 4)
  Go to: /reception/dashboard → Queue tab
  Select branch: Main Campus (must match patient's branch!)
  Filter source: App requests only
  Verify: Patient name, "App request" badge, visit reason visible

STEP 3 — Reception manages queue
  Assign doctor: siddharth.deshmukh (or any doctor)
  Click: Assign → Call → Start
  Verify: Queue status moves Waiting → Called → In service

STEP 4 — Doctor consults
  Login: siddharth.deshmukh@health360.test / SecureP@ss1!
  Go to: /doctor/opd → Begin & open (or Open encounter)
  Complete:
    - Vitals (or skip / copy last)
    - Consultation notes + assessment
    - E-prescription (at least one medicine)
    - Optional: lab order
  Mark encounter complete if prompted

STEP 5 — Reception checkout
  Login: reception (or hospital admin)
  Go to: /reception/dashboard → completed patient row
  Billing column should show: No bill yet / Payment pending / Paid
  Click: Checkout (or Collect payment)
  Create invoice → Record payment (Cash / Online / UPI / Card / Other)
  Verify: Row shows "Paid" — no duplicate checkout button

ALTERNATIVE — Walk-in (no app)
  Reception → New OPD tab → search/register patient → add to queue
  Continue from Step 3.

7b. PHASE F / G QUICK CHECKS
--------------------------------------------------------------------------------

AUTH / MFA (G10)
  1. /forgot-password → enter email → check API logs / local email for reset link
     (local logs include web + health360://reset-password?token=… for mobile)
  2. Mobile: Login → Forgot password → same API; open mobile deep link to Reset password
  2. /reset-password?token=… → set new password → login
  3. Settings → Account → Set up authenticator → Enable MFA → save backup codes
  4. Logout → login → enter TOTP (or backup code) → access portal
  5. Disable MFA with password + code

PAYMENTS (F)
  1. Unpaid invoice → Patient Payments → Pay online (sandbox OK without Razorpay keys)
  2. Hospital Admin → Subscription → renew / pay (sandbox)
  3. Desk checkout payment methods: Cash, Online, UPI, Card, Other

PARTNERS (G8)
  1. Platform Admin → Partners → create LABORATORY/PHARMACY
  2. Add location (lat/lng required) → Link hospital UUID …000030
  3. Add membership (user UUID from Users)

PHARMACY STOCK (G6)
  1. Pharmacist → Catalog → Receive stock (batch #, qty, expiry)
  2. Dispense a request → FEFO stock decreases when medicine linked

OT (G7)
  1. Procedure detail → Add implant (lot/serial)
  2. Save anesthesia chart (type + ASA) → Add VITALS event

SMS (G1)
  1. Default: SMS_PROVIDER=log → SMS lines appear in API logs when user SMS pref on
  2. Optional: SMS_PROVIDER=msg91 + SMS_AUTH_KEY (+ template for DLT Flow API)

OPD APPROACHING (G3)
  Multiple WAITING tokens; when position ≤ 3, patient gets OPD_APPROACHING once

CHECK-IN QR (G2)
  Appointment detail → QR / health360://appointments/{id}/check-in

9. KNOWN LIMITATIONS / NOTES FOR TESTERS
--------------------------------------------------------------------------------

- Appointment slot booking UI removed from main OPD flow; use Request OPD instead.
- Token numbers exist internally for queue ordering but are not shown as main UI label.
- Patient must re-login after V66 migration to get opd:request:own permission.
- Reception must select the SAME branch the patient chose when requesting OPD.
- Staff without hospital.staff record: use Hospital Admin → Staff to invite, or
  staff backfill runs on first scope API call (V63 migration).
- Desk payment methods: Cash, Online, UPI, Card, Other (no Cashless).
- MFA is optional; when enabled, web and mobile login require TOTP/backup code.
- SMS defaults to log stub; MSG91 HTTP only when SMS_PROVIDER=msg91 and SMS_AUTH_KEY set.
- PACS / LIS integrations are not in scope until hospital contracts exist.
- Shubham patient uses different password (Kadam@123) — not SecureP@ss1!
- These credentials are for LOCAL DEV ONLY — never use in production.
